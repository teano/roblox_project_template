# Product Requirements

## Product Outcome

Разработчик проекта на основе Roblox-шаблона должен иметь возможность вызвать проектный Codex skill `$csv-to-luau`, указать CSV-источник и целевой Luau-модуль и получить проверяемую таблицу данных непосредственно в файловой структуре текущего Git/Rojo-проекта. Результат должен синхронизироваться в Roblox Studio обычным контуром Rojo без отдельного Studio-плагина, локального фонового приложения или ручного копирования сгенерированного текста.

Конвертер должен безопасно создавать новый модуль данных или полностью синхронизировать уже существующий чистый модуль данных с CSV. До записи разработчик видит компактный предпросмотр схемы и изменений; неоднозначный ввод, повреждённый CSV или риск потери исполняемого Luau-кода останавливает операцию без изменения файлов.

## Target Audience

- Разработчики Roblox-проектов, созданных из этого шаблона и использующих Git, Rojo и Codex.
- Технические дизайнеры и разработчики контента, которые ведут табличные данные в CSV и хотят получать готовые ModuleScript-таблицы без ручной сериализации.
- Команды, которым нужен одинаковый, воспроизводимый процесс конвертации на Windows, macOS и Linux.

## Core Gameplay Loop

1. Пользователь вызывает `$csv-to-luau` и передаёт CSV как вложение или по явно указанному доступному пути.
2. Пользователь явно указывает целевой путь внутри текущего репозитория либо однозначно описывает, какой Luau-модуль требуется обновить.
3. Конвертер разбирает CSV, определяет разделитель и тип каждой колонки, проверяет структуру и определяет формат существующего чистого модуля либо запрашивает формат для нового файла.
4. Конвертер показывает ограниченный предпросмотр схемы, примеров результата, диагностик и ожидаемых изменений.
5. При однозначном валидном вводе конвертер создаёт или полностью синхронизирует целевой файл без дополнительного подтверждения; при неоднозначности или ошибке он ничего не меняет и задаёт один необходимый уточняющий вопрос либо сообщает диагностику.
6. После записи пользователь получает краткую сводку и Git diff/stat, а Rojo синхронизирует изменённый Luau-модуль в текущий проект.

## Release Target

Первая версия поставляется в переиспользуемом template-репозитории как проектный Codex skill `$csv-to-luau` и наследуется производными проектами. Она работает с обычными CSV-файлами и чистыми Luau-модулями данных в локальном Git/Rojo-проекте, не требует Roblox Studio для самой конвертации и использует платформенно-нейтральный Python standard library contract. Release readiness подтверждается полным deterministic suite в доступной среде; отдельные macOS/Linux прогоны и Windows directory-symlink сценарий, требующий повышенной файловой привилегии, остаются дополнительным неблокирующим evidence.

## Scope

### In Scope

- Чтение CSV из вложения или по явно указанному доступному пути.
- Создание и изменение только `.luau`-файлов внутри текущего Git/Rojo-репозитория.
- Выходной формат как массив таблиц строк или словарь по выбранной ключевой колонке.
- Корректная обработка кавычек, разделителей и переносов строк внутри кавычек, UTF-8 и UTF-8 BOM.
- Автоматическое определение разделителя отдельно для каждого входного файла.
- Определение типа по всем непустым значениям колонки с возможностью пользовательского переопределения.
- Типы `number`, `boolean`, `string`, автоматически распознаваемый `array<string>` и пустое значение `nil`, при котором поле строки не генерируется.
- Компактный предпросмотр до записи и краткая Git-сводка после записи.
- Полная синхронизация существующей генерируемой таблицы с CSV.
- Защита от недопустимых Luau-идентификаторов, небезопасных строковых литералов и изменения модулей с неоднозначным исполняемым кодом.

### Out of Scope

- Roblox Studio plugin.
- Локальное companion-приложение или постоянно работающий фоновый процесс.
- Расширение Visual Studio Code.
- Запись файлов за пределами текущего Git/Rojo-репозитория.
- Изменение Roblox DataModel напрямую в обход файлов проекта и Rojo.
- Импорт форматов электронных таблиц, отличных от CSV.
- Выполнение, вычисление или рефакторинг произвольного Luau-кода в существующем целевом модуле.
- Слияние CSV с отсутствующими в нём старыми строками или ключами; CSV является полным источником данных.
- Одновременный запуск нескольких экземпляров конвертера для одной и той же цели, их координация, ожидание или сериализация.
- Защита от перезаписи цели другим процессом или внешним writer во время выполнения конвертации.

## Functional Requirements

- `PRD-REQ-001`: Конвертер должен принимать CSV как пользовательское вложение или читать его по явно указанному доступному пути.
- `PRD-REQ-002`: Конвертер должен создавать или изменять целевой `.luau`-файл только внутри корня текущего Git/Rojo-репозитория. Попытка выхода за границу репозитория, включая перенаправление через путь, должна завершаться отказом без записи.
- `PRD-REQ-003`: Пользователь должен либо явно указать целевой путь, либо дать однозначное словесное описание целевого Luau-модуля. Если цель отсутствует или описание соответствует нескольким файлам, конвертер должен спросить пользователя и не угадывать путь.
- `PRD-REQ-004`: Для нового файла пользователь должен явно выбрать формат «массив строк» или «словарь по ключевой колонке». Если формат не указан, конвертер должен спросить его до записи.
- `PRD-REQ-005`: Для распознанного существующего чистого модуля данных конвертер должен определить текущий формат таблицы и обновить его без повторного вопроса о формате. Если формат нельзя определить надёжно, операция должна остановиться и запросить уточнение.
- `PRD-REQ-006`: Новый файл должен создаваться без дополнительного подтверждения, когда входной CSV, целевой путь, формат и необходимые параметры однозначны и прошли валидацию.
- `PRD-REQ-007`: Распознанный существующий файл должен обновляться без дополнительного подтверждения после предпросмотра, когда все проверки безопасности и валидации пройдены.
- `PRD-REQ-008`: Конвертер должен поддерживать CSV-поля в кавычках, удвоенные кавычки внутри поля, разделители внутри поля, переносы строк внутри поля, окончания строк разных платформ, UTF-8 и необязательный UTF-8 BOM.
- `PRD-REQ-009`: Разделитель должен определяться заново для каждого CSV. Если несколько вариантов остаются правдоподобными и выбор влияет на структуру данных, конвертер должен показать кандидатов, спросить пользователя и не изменять файл.
- `PRD-REQ-010`: Полностью пустые физические строки вне поля в кавычках должны игнорироваться. Пустые строки внутри поля в кавычках должны сохраняться как часть строкового значения.
- `PRD-REQ-011`: Значения без кавычек должны очищаться от пробелов по краям. Содержимое поля в кавычках должно сохраняться буквально, включая крайние пробелы, до последующего преобразования по effective type колонки; `array<string>` дополнительно применяет правила элементов из `PRD-REQ-036`.
- `PRD-REQ-012`: Пустая ячейка после разбора и нормализации должна иметь значение `nil`; соответствующее поле не должно записываться в таблицу строки.
- `PRD-REQ-013`: Логическая запись, в которой после нормализации пусты все колонки, включая записи вида `,,` и `"","",""`, должна завершать валидацию ошибкой с указанием строки. Конвертер не должен генерировать пустую таблицу строки `{}`.
- `PRD-REQ-014`: Частично заполненная запись должна быть допустима, если она выполняет остальные правила режима. Пустые поля такой записи не должны присутствовать в сгенерированной таблице.
- `PRD-REQ-015`: Заголовок должен содержать непустое уникальное имя для каждой колонки. Пустые или повторяющиеся имена должны завершать операцию ошибкой до записи.
- `PRD-REQ-016`: Каждая логическая запись данных должна содержать ровно столько колонок, сколько заголовок. Иное количество колонок должно завершать операцию ошибкой с указанием записи.
- `PRD-REQ-017`: Тип должен определяться по всей колонке: пустые значения не участвуют; если без явного type override хотя бы одна непустая ячейка содержит запятую, тип всей колонки равен `array<string>`; иначе если все непустые значения являются допустимыми числами, тип равен `number`; если все являются `true` или `false` без учёта регистра, тип равен `boolean`; во всех остальных случаях тип равен `string`.
- `PRD-REQ-018`: Числоподобные значения с незначащими ведущими нулями, например `00123`, должны оставаться строками, чтобы не повреждать идентификаторы.
- `PRD-REQ-019`: Булевы значения должны распознаваться без учёта регистра и генерироваться как канонические Luau-значения `true` и `false`.
- `PRD-REQ-020`: Предпросмотр должен показывать выведенный тип каждой колонки. Пользователь должен иметь возможность переопределить отдельную колонку как `string`, `number` или `boolean`; явный `string` должен сохранять comma-separated ячейку одной строкой вместо автоматического массива, а несовместимое с данными переопределение должно завершаться явной ошибкой без записи.
- `PRD-REQ-021`: Колонка без непустых значений должна явно отмечаться в предпросмотре как не содержащая данных; её поля не генерируются, пока пользователь не предоставит непустые значения, а переопределение типа не должно создавать значения из пустых ячеек.
- `PRD-REQ-022`: В режиме массива конвертер должен генерировать одну таблицу на каждую валидную запись в порядке записей CSV.
- `PRD-REQ-023`: В режиме словаря пользователь должен выбрать ключевую колонку. Пустой ключ или повтор ключа после преобразования к выведенному либо переопределённому типу должен завершать операцию ошибкой без записи.
- `PRD-REQ-024`: Ключ словаря должен сохранять тип выбранной колонки: строковый ключ остаётся строкой, числовой — числом, булев — булевым. Ключевая колонка должна также оставаться внутри вложенной таблицы строки.
- `PRD-REQ-025`: Текстовое расположение словарных записей в генерируемом файле должно следовать порядку записей CSV для стабильного результата; конвертер не должен обещать порядок обхода словаря во время выполнения Luau.
- `PRD-REQ-026`: Допустимые Luau-идентификаторы заголовков должны генерироваться обычными полями, например `name = ...`. Все остальные заголовки должны сохраняться без переименования через строковый ключ, например `["display name"] = ...`.
- `PRD-REQ-027`: Все строковые значения и строковые ключи должны экранироваться так, чтобы результат оставался валидным Luau и буквально сохранял кавычки, обратные косые черты, управляющие символы и переносы строк из CSV.
- `PRD-REQ-028`: До записи конвертер должен показать ограниченный предпросмотр: источник и цель, определённый разделитель, число записей и колонок, схему типов, режим и ключевую колонку, количество пустых значений и диагностики, несколько первых и последних преобразованных записей.
- `PRD-REQ-029`: Для существующего файла предпросмотр должен дополнительно показывать количество добавленных, изменённых и удалённых строк или типизированных ключей. Полное содержимое допускается показывать только для небольшого результата; многотысячный файл не должен целиком выводиться в чат.
- `PRD-REQ-030`: CSV должен быть полным источником данных. При обновлении существующей таблицы строки или ключи, отсутствующие во входном CSV, должны удаляться из результата.
- `PRD-REQ-031`: Автоматически обновляться может только чистый модуль данных, исполняемое содержимое которого является единственным табличным `return { ... }`. Директива `--!strict` и комментарии перед `return` должны сохраняться.
- `PRD-REQ-032`: Если существующий файл содержит `require`, функции, вычисляемые выражения, метатаблицы, дополнительный исполняемый код, комментарии внутри возвращаемой таблицы или другую неоднозначную конструкцию, конвертер должен не менять файл и спросить пользователя, как поступить.
- `PRD-REQ-033`: После успешной записи конвертер должен показать краткое описание результата и Git diff/stat только для затронутого целевого файла.
- `PRD-REQ-034`: Любая ошибка разбора, валидации, определения цели, режима или безопасности должна завершаться до изменения целевого файла и содержать достаточную диагностику для исправления входа.
- `PRD-REQ-035`: Повторная конвертация одинакового CSV с одинаковыми параметрами в неизменный целевой файл не должна создавать содержательных изменений.
- `PRD-REQ-036`: В колонке `array<string>` каждая непустая ячейка должна разделяться по запятым на строки с удалением пробелов по краям элементов и сохранением порядка. Одиночное значение в этой колонке должно генерироваться как одноэлементный массив. Пустой элемент, массив в key column или превышение общего лимита генерируемых значений должны завершаться ошибкой до записи. Существующий чистый модуль с такими одноуровневыми строковыми массивами должен безопасно распознаваться при повторной синхронизации.
- `PRD-REQ-037`: Для колонок, которые остались скалярными без explicit override, предпросмотр должен анализировать непустые ячейки на вероятные массивы с разделителями `semicolon`, `pipe`, `tab` и `newline`. Валидный кандидат должен называть колонку и разделитель, показывать ограниченные counts/sample и останавливать запись до решения пользователя. Пользователь должен иметь возможность явно выбрать разделитель массива для конкретной колонки либо сохранить колонку строковой; никакой нестандартный разделитель не должен автоматически менять тип данных без этого решения.

## Quality Requirements

- `PRD-NFR-001`: Одинаковые входные байты и параметры должны давать побайтно одинаковый Luau-результат независимо от platform-specific line endings и shell behavior. Реализация не должна содержать OS-specific ветвей генерации; отдельное выполнение suite на каждой desktop OS не является обязательным release-гейтом.
- `PRD-NFR-002`: Запись должна быть отказоустойчивой: ошибка не должна оставлять частично перезаписанный или обнулённый целевой файл.
- `PRD-NFR-003`: Все диагностические сообщения должны называть входной файл, а для ошибок данных — логическую запись и, когда применимо, колонку.
- `PRD-NFR-004`: Предпросмотр и итоговая сводка должны иметь ограниченный размер, не зависящий линейно от количества записей в большом CSV.
- `PRD-NFR-005`: Конвертер должен обрабатывать CSV с многострочными полями как логические записи и не выдавать физическую строку внутри кавычек за отдельную запись.
- `PRD-NFR-006`: Сгенерированный файл должен быть валидным UTF-8 Luau-модулем и сохранять все поддерживаемые Unicode-значения без повреждения.
- `PRD-NFR-007`: Валидный результат должен загружаться Luau runtime без ошибки синтаксиса, включая таблицы с заголовками, которые не являются допустимыми идентификаторами.
- `PRD-NFR-008`: Конвертер не должен зависеть от платформенно-специфичного shell-синтаксиса или отдельного постоянно работающего процесса.
- `PRD-NFR-009`: Конвертер не должен добавлять внешние зависимости в проект без отдельного явного разрешения пользователя.
- `PRD-NFR-010`: Проверка границы репозитория должна выполняться по фактическому целевому расположению и не допускать обхода через относительные сегменты или файловые перенаправления.
- `PRD-NFR-011`: Валидация должна завершаться до записи всего результата; при нескольких обнаруживаемых ошибках предпросмотр должен давать компактную полезную сводку без вывода содержимого всего CSV.
- `PRD-NFR-012`: Для существующего файла автоматическое обновление должно быть консервативным: сомнение в распознавании структуры считается отказом, а не разрешением на перезапись.

## Acceptance Criteria

- `PRD-AC-001`: Для валидного CSV и явно выбранного режима массива создаётся ModuleScript, возвращающий записи в исходном порядке, а пустые поля отсутствуют в таблицах строк.
- `PRD-AC-002`: Для нового файла без указанного формата конвертер задаёт вопрос о формате и не создаёт файл.
- `PRD-AC-003`: При отсутствующей или неоднозначно описанной цели конвертер перечисляет найденную неоднозначность, спрашивает пользователя и не изменяет ни один `.luau`-файл.
- `PRD-AC-004`: Явная попытка записать результат за пределы текущего репозитория завершается отказом, и внешний файл не создаётся и не изменяется.
- `PRD-AC-005`: CSV с BOM, запятой и кавычкой внутри экранированного поля и переносом строки внутри кавычек преобразуется в одну корректную логическую запись; explicit `string` override сохраняет полный текст этой ячейки без array conversion.
- `PRD-AC-006`: Для файла с однозначным нестандартным разделителем разделитель определяется на лету; для неоднозначного файла показываются кандидаты и запись не выполняется до ответа пользователя.
- `PRD-AC-007`: Колонка `1`, `-2`, `3.5` определяется как `number`; `TRUE`, `false`, `True` — как `boolean`; смешанная колонка — как `string`; `00123` не преобразуется в число.
- `PRD-AC-008`: Пользователь может переопределить числоподобную колонку как `string`, после чего её значения генерируются строками; несовместимое переопределение как `boolean` отклоняется без записи.
- `PRD-AC-009`: Заголовки `name`, `display name` и `end` сохраняются соответственно как обычное поле для допустимого идентификатора и как безопасные строковые ключи для недопустимого имени или зарезервированного слова.
- `PRD-AC-010`: Пустой или повторяющийся заголовок завершает операцию ошибкой до создания или перезаписи цели.
- `PRD-AC-011`: Запись с иным количеством колонок, чем заголовок, завершает операцию ошибкой с номером логической записи; пустая ячейка при корректном числе разделителей не считается отсутствующей колонкой.
- `PRD-AC-012`: Полностью пустая физическая строка между записями игнорируется, но запись `,,` или `"","",""` отклоняется как не содержащая данных и никогда не превращается в `{}`.
- `PRD-AC-013`: Запись `,Bob,` в режиме массива создаёт `{ name = "Bob" }`; в режиме словаря по пустой колонке `id` та же запись отклоняется из-за отсутствующего ключа.
- `PRD-AC-014`: Два разных текстовых представления, которые после типизации образуют один ключ, выявляются как дубликат; целевой файл остаётся неизменным.
- `PRD-AC-015`: В словаре по числовой ключевой колонке ключ генерируется числом и одновременно остаётся полем вложенной записи; исходный порядок записей сохраняется в тексте файла.
- `PRD-AC-016`: Кавычки, обратные косые черты, Unicode и переносы строк в строковом значении генерируют синтаксически валидный Luau и после загрузки дают исходное строковое значение.
- `PRD-AC-017`: Для большого CSV предпросмотр содержит счётчики, схему, диагностики и ограниченные первые/последние примеры, но не публикует весь сгенерированный модуль в чат.
- `PRD-AC-018`: При полной синхронизации существующего массива или словаря предпросмотр показывает добавления, изменения и удаления, а успешный результат не содержит записей, удалённых из CSV.
- `PRD-AC-019`: Чистый модуль с `--!strict`, заголовочными комментариями и единственным `return { ... }` обновляется автоматически с сохранением директивы и заголовочных комментариев.
- `PRD-AC-020`: Модуль с `require`, функцией, вычислением, метатаблицей, дополнительным исполняемым кодом или комментарием внутри таблицы не изменяется; конвертер сообщает причину и спрашивает пользователя.
- `PRD-AC-021`: Валидный новый файл создаётся после предпросмотра без отдельного запроса подтверждения, а валидный распознанный существующий файл аналогично обновляется без повторного вопроса о формате или перезаписи.
- `PRD-AC-022`: Искусственно вызванная ошибка записи не оставляет частичный результат, а прежний существующий файл остаётся доступным в исходном состоянии.
- `PRD-AC-023`: Один набор входных байтов и параметров создаёт детерминированный файл в полном suite доступной среды; повторный запуск поверх этого результата даёт пустой содержательный diff. Дополнительные macOS/Linux прогоны и Windows directory-symlink сценарий при наличии соответствующей привилегии сохраняются как полезные неблокирующие проверки.
- `PRD-AC-024`: После успешной операции пользователь видит точный целевой путь, число записанных записей и ограниченный Git diff/stat; после отказа Git diff цели отсутствует.
- `PRD-AC-025`: CSV-ячейка `"rbxassetid://123456,rbxassetid://1234562"` в колонке `Assets` генерирует `Assets` как Luau-массив из двух строк, а одиночные значения других записей той же колонки — как одноэлементные массивы. Повторная синхронизация результата даёт пустой содержательный diff; explicit `Assets=string` сохраняет исходную comma-separated строку.
- `PRD-AC-026`: Для скалярной колонки с ячейкой `rbxassetid://1|rbxassetid://2` предпросмотр предлагает `pipe` как кандидат и не записывает цель. После явного выбора `Assets=pipe` колонка генерируется как `array<string>`; после решения сохранить `Assets=string` она остаётся одной строкой. Пустые элементы выбранного массива отклоняются до записи.

## Assumptions

- Skill выполняется Codex с доступом на чтение входного файла и с доступом на запись в текущий репозиторий.
- Текущий репозиторий имеет корректную Git/Rojo-структуру; синхронизация уже записанного `.luau`-файла в Studio остаётся ответственностью существующего Rojo-контура.
- Целевые модули предназначены для статических данных и возвращают таблицу непосредственно через `return`.
- Точная техническая грамматика допустимых конечных чисел будет определена спецификацией при сохранении подтверждённых правил типизации, ведущих нулей и отказа на несовместимом переопределении.
- Колонка без непустых значений не требует выбранного runtime-типа, потому что она не создаёт ни одного поля; предпросмотр всё равно явно показывает отсутствие данных.
- Один пользовательский запуск обрабатывает одну цель; пользователь не запускает несколько конвертаций одной и той же цели одновременно.
- Отсутствие отдельного macOS/Linux runner или Windows-привилегии создания directory symlink не блокирует выпуск, если полный suite доступной среды, path traversal/junction coverage и остальные обязательные проверки проходят.

## Risks

- Эвристика разделителя или типа может быть неоднозначной на коротком или однородном CSV; fail-closed вопрос пользователю предотвращает тихую порчу структуры.
- Запятая в обычном тексте без намерения создать массив автоматически выбирает `array<string>`; явный type override `header=string`, показанный в preview, является предусмотренным способом сохранить такую ячейку одной строкой.
- Полная синхронизация намеренно удаляет отсутствующие в CSV данные; предпросмотр added/changed/removed и запрет на изменение неоднозначного модуля уменьшают риск неожиданной потери.
- Очень большие CSV могут потреблять значительное время и память; техническая спецификация должна установить разумные диагностируемые пределы, не меняя требование ограниченного вывода в чат.
- Комментарии внутри таблицы нельзя надёжно привязать к строкам после полной синхронизации; поэтому такой файл требует явного решения пользователя.
- Неправильно выбранная ключевая колонка может изменить форму доступа к данным; явный выбор, типизированная проверка уникальности и предпросмотр должны сделать результат наблюдаемым до записи.
- Внешний процесс может изменить цель во время конвертации; такое взаимодействие не поддерживается, поэтому конвертер не обещает координацию, compare-and-swap или защиту от lost update вне собственного последовательного запуска.
- Поведение на недоступной desktop OS не подтверждается отдельным release run; риск ограничивается платформенно-нейтральным standard-library implementation contract и дополнительными неблокирующими прогонами при появлении runner.
