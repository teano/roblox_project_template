# Ручная проверка локального предложения группы

Проверка использует два настоящих клиента Studio и существующие физические
окна. Перед запуском выполнить установленную проверку Rojo и выбрать
совпадающий сеанс Studio по записанным идентификаторам места и игры.

Начать новый сервер с двумя клиентами. На сервере вручную вызвать:

```luau
local qa = require(game.ServerScriptService.Tests.FriendInvitationsStudioQa)
print(qa.Read())
```

Из результата взять фактические отрицательные `UserId` обоих игроков. Оба
должны быть загруженными владельцами разных свободных слотов без друзей,
резервов и ожидающих операций. Передать номера в указанном порядке:

```luau
local qa = require(game.ServerScriptService.Tests.FriendInvitationsStudioQa)
print(qa.Prepare(inviterUserId, targetUserId))
```

На целевом клиенте физически нажать кнопку отказа в появившемся окне. Через
`qa.Read()` проверить закрытие предложения, отсутствие резерва, сохранение
слотов и отсутствие нового персонажа. Выполнить `qa.Cleanup()`; результат
должен содержать `Cleaned=true`.

Снова вызвать `qa.Prepare()` для той же пары и физически нажать кнопку
принятия. Через `qa.Read()` проверить итоговую связь, счётчики обоих игроков,
смену роли, слота, команды и точки появления цели. Для цели ожидается ровно
одно событие появления персонажа. Проверить управление персонажем на каждом
клиенте и отсутствие неожиданных ошибок сервера и клиентов.

Сохранить результат, вызвать `qa.Cleanup()` и остановить тестовый сервер.
Очистка возвращает внедрённые функции и отменяет незавершённое предложение;
успешно завершённый перенос не обращается вспять. Для повторной проверки
принятия начать новый тестовый сервер. Выход участника, ошибка подготовки,
уничтожение моста и завершение сервера также запускают очистку.

## Граница подтверждения

Сценарий вручную вызывает настоящий серверный `FriendsModule:RequestInvite`
для выбранной пары. Дружба этой пары заменена проверочным ответом. Только
копия номера цели в исходящем резерве преобразуется в положительное число,
необходимое для показа снимка; настоящие игроки и состояние резерва сохраняют
свои исходные номера. Проверочный номер не обозначает учётную запись Roblox.

Принятие и отказ поступают из физического окна через обычный протокол связи.
Сценарий подтверждает обработку этого ответа, перенос слота, счётчики и
возрождение настоящего персонажа. Он не подтверждает запрос приглашения из
клиентского списка друзей, настоящую дружбу Roblox, системное окно приглашения,
доставку внешнего приглашения или межсерверный переход. Публикация не требуется.
