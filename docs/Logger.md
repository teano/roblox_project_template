# Logger

`ReplicatedStorage/Shared/Util/Logger` — общий side-neutral адаптер для
структурированного вывода в Roblox Output. Он форматирует и маршрутизирует
записи, но не сохраняет их, не отправляет по сети и не определяет политику
телеметрии.

## Создание

```lua
local Logger = require(ReplicatedStorage.Shared.Util.Logger)

local logger = Logger.new("Save.Global", "info")
logger:Info("load_completed", {
	UserId = player.UserId,
	Revision = revision,
})
```

Допустимые уровни: `debug`, `info`, `warn`, `error`. Значение `minLevel`
отбрасывает записи меньшего уровня до форматирования полей. Неизвестный уровень
считается ошибкой конфигурации и отклоняется конструктором.

`Debug` и `Info` используют `print`; `Warn` и `Error` используют `warn`.
`Error` является уровнем журнала и не выбрасывает исключение. Решение об
остановке операции всегда остаётся за вызывающим кодом.

## Формат и безопасность

Стандартный формат:

```text
[level] [scope] message Key="Value"
```

Поля сортируются по итоговому строковому представлению, поэтому порядок
стабилен. Строки экранируют обратную косую черту, кавычки, переводы строк,
табуляцию и остальные управляющие символы; одна запись всегда остаётся одной
строкой.

Logger ограничивает уже экранированные значения по числу байт:

| Часть записи | Лимит |
|---|---:|
| Scope | 128 |
| Message | 1024 |
| Имя поля | 64 |
| Значение поля | 512 |
| Полная строка | 4096 |

Обрезанные значения завершаются маркером `<truncated>`.

Преобразование значений через `tostring` защищено. Падающий `__tostring`
заменяется на `<unprintable:TYPE>`, а ошибка форматирования всей таблицы полей
создаёт безопасную запись `log_format_failed`. Ошибка самого output sink также
не выходит из Logger и не маскирует исходную ошибку приложения.

Это не снимает с вызывающего кода ответственность за содержимое полей. Не
передавайте секреты, токены, полные save-документы или другие данные, которые
не должны попадать в Output.

## Дочерние логгеры и sink

`Child(scope)` добавляет сегмент к текущему scope и наследует `minLevel` и
output sink:

```lua
local storageLogger = logger:Child("Storage")
```

Для тестов или интеграции с другим локальным выводом конструктор принимает
необязательный третий аргумент:

```lua
local sink = {
	Print = function(line)
		-- обычный вывод
	end,
	Warn = function(line)
		-- предупреждения и ошибки
	end,
}

local testLogger = Logger.new("Test", "debug", sink)
```

Обе функции sink получают одну готовую строку. Logger не предоставляет
хранилище, HTTP-транспорт, глобальный rate limiter или автоматическое скрытие
секретов. Такие политики добавляются только при появлении конкретного
production-потребителя.

## Проверка

В Studio Play из серверной командной строки:

```lua
require(game.ServerScriptService.Tests.LoggerTestRunner).runAll()
```

Набор проверяет фильтрацию уровней, маршрутизацию, стабильный формат,
экранирование, лимиты, дочерние scope, падающие `__tostring` и sink, а также
runtime-валидацию конфигурации. Успешный результат содержит `failed = 0`.
